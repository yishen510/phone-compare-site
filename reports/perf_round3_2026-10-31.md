# 性能优化第三轮：候选评估与 A/B 记录

## 一、目标与指标（沿用第二轮）

- 目标：在不改变功能与视觉的前提下降低首屏成本
- 指标：首张卡片可见、全部画完、`LayoutDuration` / `RecalcStyleDuration` / `ScriptDuration`（CDP `Performance.getMetrics`）

## 二、本轮尝试的 3 个候选

| 候选 | 方法 | 实测结果 | 处理 |
| --- | --- | --- | --- |
| **`contain:layout style`（卡片）** | 加 CSS 后跑 2 次，再**移除**跑 1 次做 A/B | 保留时 Layout 3178 / 2494ms；**移除后 2447ms（反而略好）**；同期 Script 393→263，说明差异主要来自系统负载 | **不采用** |
| **表格行 `content-visibility`** | 给 `tbody tr` 加 `content-visibility:auto` | 切表格 1546ms（移除前 1309ms）、Layout 2372ms（移除前 2447ms），无显著差异 | **回退** |
| **`warmSearchIndex` 自适应** | 固定 24 条/批 → 按 `timeRemaining()` 自适应（单批上限 40） | 不影响首屏指标；单次 idle 任务变短 | **保留** |

> 这一轮最重要的产出不是"改了什么"，而是**证明两个看起来合理的 CSS 优化并无收益**，避免把系统负载波动误判为优化成果。

## 三、保留的改动与预期收益

**改动**：`warmSearchIndex()` 的预热分批策略

```
固定 24 条/批  →  按 idle 剩余时间自适应（timeRemaining < 2ms 就让出，单批不超过 40 条）
```

**预期收益**：
- 单次 idle 任务不再吃满 8ms，**减少预热期间对滚动/输入的阻塞**（首屏之后用户可能立刻滚动）
- 总预热工作量不变，完成时间可能略晚（仍在空闲期），**不影响首屏指标**
- 顺带修一个隐患：测试桩里 `timeRemaining()` 恒为 8（不递减）时，原实现会一次性构建全部 485 条；加 40 条/批上限后不会退化成同步长任务

**可观测性说明**：首屏 bench 不测 idle 期任务，所以这项收益无法用现有指标量化，属于"减少长任务"的定性改进。

## 四、为什么本轮没有更多改动（关键结论）

1. **瓶颈仍在浏览器布局**：首屏 Layout 占 50–56%，Script 仅 5–6%。JS 侧在前两轮已完成预计算、缓存、分批等优化。
2. **测量波动大于可优化空间**：同一版本多次测量，Layout 在 2372–3882ms 之间（±25%），首张卡片 2160–3711ms（±40%）。**小于 20% 的优化无法可靠验证**。
3. **大于 20% 的优化只剩结构性方案**（见下表），均超出"功能与行为完全不变"的约束。

## 五、真正能突破的方案（需单独评估，本轮未做）

| 方案 | 预期收益 | 风险 / 代价 |
| --- | --- | --- |
| 虚拟滚动（只渲染可视行） | 首屏可能降到 1–2s | 接管滚动与高度估算，搜索/收藏/对比状态易出错，回归风险高 |
| 降级毛玻璃（去掉 `backdrop-filter`） | 明显降低合成成本 | 视觉风格改变，违反"外观不变" |
| 拆分外部 JSON | 首屏解析大幅下降 | 破坏单文件站点结构，离线直开退化 |
| 精简卡片 DOM（`::before` 替代 5 个 `<small>`） | 可能降 Layout 5–10% | 收益低于测量波动、无法可靠验证；伪元素文本对读屏不如真实文本稳 |
